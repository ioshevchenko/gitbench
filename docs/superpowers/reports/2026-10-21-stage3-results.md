# Этап 3: итоги (ветка stage3-diff)

## Сделано
- Перенесено сравнение текстов IntelliJ (`platform/util/diff` и классы сравнения из `diff-api` и `diff-impl`). Его 81 оригинальный тест проходит. Этот же модуль пойдёт в 3-way merge на этапе 4.
- Редактор Diff (вкладка редактора):
  - **Side-by-side:** две колонки с номерами строк, полоса с кривыми между ними, цвета New UI, подсветка слов, линия на месте вставки, синхронная прокрутка.
  - **Unified:** одна колонка, две колонки номеров строк.
  - Кнопка `>>` возвращает блок (Revert) или принимает его (Accept). С `Ctrl` блок дописывается (Append). `Ctrl+Alt+R` применяет блок под кареткой.
  - Правая сторона — общий буфер рабочего файла. Правки, отметка «изменён» и `Ctrl+S` общие с открытым C-редактором.
  - Diff считается заново через 300 мс после ввода.
  - Тулбар: Previous/Next Difference (`Shift+F7`/`F7`), Previous/Next File (`Alt+Shift+Left/Right`), выбор вьюера, счётчик различий, шестерёнка с Ignore и Highlighting.
  - Сообщения как в IntelliJ: «Contents are identical», «Differences ignored», «Files contents are different» (бинарный файл), «Files are too large to compare».
  - Подсветка C/C++ из CDT. Без CDT diff работает без подсветки.
- Открытие diff:
  - Commit-вид: двойной клик по файлу и Show Diff (`Ctrl+D`).
  - Git Log: двойной клик по файлу коммита, контекстное меню Show Diff и Jump to Source (`F4`).
  - Если выбран один файл, Previous/Next File идут по всем файлам дерева. Если выбрано несколько, только по ним.
  - После коммита или checkout открытый diff перечитывает сторону HEAD.
- Финальное ревью (отдельный ревьюер) и исправления:
  - изменения буфера после Rollback и checkout теперь идут в UI-потоке (раньше без открытого C-редактора ломался текст);
  - Unified не падает при «Ignore whitespaces and empty lines»;
  - событие репозитория больше не сбрасывает прокрутку;
  - `Ctrl+Alt+R` не вставляет символ на раскладках с AltGr;
  - исходник растеризатора иконок теперь в git (раньше его скрывало правило `build/` в `.gitignore`).
- По скриншоту пользователя: колонки номеров строк больше не белые в тёмной теме. Серый текст в деталях коммита и в таблице Git Log читается на тёмном фоне.
- Тесты: 509, все зелёные, 1 пропущен (как в оригинале графа). Jar лежит в dropins CubeIDE.

## Отступления от IntelliJ
- Кнопки `>>` нарисованы на полосе между колонками, а не в зеркальном поле левой колонки. `SourceViewer` не умеет ruler справа.
- В Unified нельзя набирать текст, только применять блоки кнопкой `>>`.
- Кнопки `x` нет. В двухколоночном diff IntelliJ её тоже нет, она есть только в merge (этап 4).
- Previous/Next File сохраняют рабочий файл перед переходом. В IntelliJ документ живёт в памяти, а здесь без открытого C-редактора правки бы потерялись.

## Не сделано
- Отложенные мелочи ревью:
  - фильтр дисплея может утечь, если виджеты закрылись раньше редактора;
  - нет суффикса « (Read-only)» в заголовке колонки;
  - Previous/Next File только выключаются, а не прячутся;
  - у полосы нет контура;
  - сообщение «only line separators» ошибается для CRLF-блоба;
  - после коммита нового файла diff не перечитывается;
  - клик `>>` в первые 300 мс после ввода пропускается;
  - нет `validateState` перед правкой;
  - вся подсветка пересчитывается после каждой паузы в вводе;
  - перевод Edit в смещения документа без отдельного теста;
  - файл вне workspace не делит буфер с File > Open File;
  - shim `StringUtil`;
  - если детали коммита не загрузились, все файлы показаны как добавленные.
- Автотестов UI нет: тесты плагина идут без Eclipse. UI проверяется вручную.
- Ветка не слита в main: решение после ручной проверки.

## Что проверить руками
1. Commit-вид: двойной клик по изменённому `.c` файлу. Цвета, кривые, подсветка слов и синтаксиса.
2. `>>` возвращает блок. Изменение видно в открытом C-редакторе. `Ctrl+S` сохраняет.
3. Ввод текста справа обновляет diff.
4. Unified, Ignore и Highlighting переключаются и запоминаются.
5. `F7`, `Shift+F7`, `Alt+Shift+Left/Right`, `Ctrl+Alt+R` работают и не заняты Eclipse.
6. Git Log: diff файла коммита с родителем.
7. Новый, удалённый, переименованный и бинарный файлы.
8. Rollback в Commit-виде, пока открыт diff этого файла без C-редактора.
9. Коммит другого файла, пока diff прокручен вниз: прокрутка остаётся.
