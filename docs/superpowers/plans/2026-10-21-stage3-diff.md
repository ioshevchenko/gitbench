# Этап 3: split и unified diff — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Редактор Gitbench Diff с двумя режимами, как diff в IntelliJ: **Side-by-side** (две колонки, разделитель с кривыми, кнопки `>>`) и **Unified** (одна колонка). Редактор открывается из видов Commit и Git Log.

**Architecture:** Сравнение текстов — перенесённый без изменений модуль IntelliJ `platform/util/diff` (Kotlin, Apache 2.0). К нему добавляется `ComparisonManagerImpl` из `platform/diff-impl`. Перенос сделан тем же способом, что граф на этапе 2: оригинальные тесты сравнения тоже переносятся и доказывают точность порта. Новый Java-код:
- `gitbench.diff`: загрузка содержимого сторон, модель изменений, unified-модель, применение блока;
- `gitbench.ui.diff`: Eclipse-редактор, split- и unified-вьюеры на `SourceViewer`.

Чистый код тестируется на временных репозиториях и строках. UI проверяет пользователь в CubeIDE.

**Tech Stack:** Java 17, Kotlin (только перенесённый код), Gradle + Shadow, JUnit 5 + Vintage, AssertJ, Eclipse 4.33 API (`org.eclipse.jface.text`, `org.eclipse.core.filebuffers`, `org.eclipse.ui.editors`), CDT UI как необязательная зависимость.

**Spec:** `D:\Projects\gitbench\docs\superpowers\specs\2026-10-21-gitbench-design.md`, раздел «Части системы → 3. Split и unified diff», «Что решает строитель».

## Review Focus

1. **CRLF в рабочем файле, LF в git.** Файл с `core.autocrlf=true` или с CRLF на диске: diff показывает только реально изменённые строки, а не весь файл. Тест в Task 2: `crlfAndLfTextsWithSameLinesHaveNoChanges`.
2. **Не-UTF-8 и BOM.** Файл в windows-1251 или UTF-8 с BOM: обе стороны читаются в одной кодировке, кириллица не ломается, BOM не даёт изменения в первой строке. Тесты в Task 4: `decodesRevisionWithWorkspaceCharset`, `utf8BomIsNotAChange`.
3. **Бинарный файл.** `.bin` или `.elf` в Commit-виде: редактор показывает «Binary files differ» и не грузит весь файл в `StyledText`. Тест в Task 4: `binaryContentIsDetected`.
4. **Нет одной из сторон.** Новый, удалённый, unversioned и переименованный файл, корневой коммит в Git Log. Пустая сторона подписана, исключений нет, у переименованного файла слева старый путь. Тесты в Task 4: `addedFileHasEmptyLeft`, `deletedFileHasEmptyRight`, `renamedFileUsesOldPathOnLeft`, `rootCommitHasEmptyLeft`.
5. **Правка рабочего файла в diff, пока файл открыт в редакторе C.** Обе вкладки показывают один документ, dirty-флаг общий, `>>` попадает в открытый редактор. Это делает общий file buffer (Task 6). Автотеста нет, пункт входит в ручную проверку.
